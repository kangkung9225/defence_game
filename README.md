# 2D 횡스크롤 라인 디펜스 게임 프로젝트

앱 개발 원정대 팀원들이 함께 만드는 2~4주 단기 2D 라인 디펜스 미니 게임 프로젝트입니다.  
Unity + VS Code + 각자의 AI 도구를 활용하여 협업하며, 최종적으로 구글 플레이스토어 출시를 목표로 합니다.

---

## 1. 프로젝트 개요 및 환경
- 장르: 2D 횡스크롤 라인 디펜스
- 엔진 버전: Unity 6.6 (6000.6.9f1) (팀원 전원 버전 통일)
- 렌더 파이프라인: 2D URP (Universal Render Pipeline)
- .NET SDK: .NET SDK 8.0.428 (LTS)
- 대상 플랫폼: Android (Google Play Store 출시 목표) & PC Editor 테스트
- 최소 테스트 기기 사양: Android 8.0 (Oreo / API Level 26) 이상 탑재 스마트폰 또는 태블릿

## 3. 프로젝트 개발 단계 및 워크플로우

단기(2~4주) 목표 달성을 위해 아래 4단계로 순차 진행됩니다.

```
[1단계: 기초 기획 및 목업]
  ├─ 게임 배경/스토리 및 페르소나(아군/적군 컨셉) 확정
  ├─ 레벨 디자인 초안 및 UI/UX 화면 목업 설계
  └─ 스키마 구조(유닛 스탯, 재화, 스테이지 데이터 테이블) 기획

[2단계: 기초 에셋 & 프로토타입 개발]
  ├─ 기초 그래픽 에셋(배경, 기지 건물, 유닛 스프라이트) 및 사운드 제작
  ├─ 기본 코어 로직(코스트 충전, 소환, 라인 이동, 사거리 인식, 전투/공격, 기지 체력) 구현
  └─ 더미(임시) 리소스로 첫 플레이어블 프로토타입 완성

[3단계: 시스템 통합 & 콘텐츠 확장]
  ├─ 완성된 그래픽/사운드 에셋을 프로토타입에 결합
  ├─ 스테이지/웨이브 스폰 시스템 및 승리/패배 결과창 연결
  └─ 로컬 데이터 저장(유닛 해금, 재화 저장 등) 연동

[4단계: QA 테스트 & 구글 플레이 출시]
  ├─ 팀원 및 테스터 대상 내부 테스트 APK 배포
  ├─ 버그 수정 및 유닛 간 스탯 밸런스 미세 조정
  └─ 구글 플레이 규격(.aab) 최종 빌드 및 스토어 배포
```

## 4. 리소스(에셋) 제작 및 업로드 규격

모든 리소스는 표준화된 확장자와 명명 규칙을 준수하여 프로젝트에 추가합니다.

- 2D 이미지/스프라이트:
  - 허용 확장자: .webp (권장: 투명 알파 지원, 경량화), .png
  - 저장 위치: Assets/Sprites/ (하위 Units/, Environments/, UI/ 구분)
  - Unity 텍스처 규격: Texture Type: Sprite (2D and UI), PPU(Pixels Per Unit): 100 기본 통일
- 오디오 (사운드):
  - 배경음악 (BGM): .mp3 또는 .ogg (루프 재생 최적화)
  - 효과음 (SFX): .wav (레이턴시 최소화, 16bit / 44.1kHz 권장)
  - 저장 위치: Assets/Audio/ (하위 BGM/, SFX/ 구분)
- 데이터 테이블/기획 문서:
  - 형식: .json 또는 .csv (게임 내 데이터 연동용)
  - 저장 위치: Assets/Data/

## 5. GitHub 이슈(Issues) 관리 규칙

팀원 간 작업 중복을 막고 버그를 효율적으로 추적하기 위해 GitHub Issues를 활용합니다.  
작업을 시작하기 전 이슈를 먼저 등록하거나, 발견한 버그/아이디어를 이슈로 남겨주세요.

### 📌 이슈 제목 규칙 (말머리 사용)
- [기능] 구현할 기능 요약 (예: [기능] 아군 기본 유닛 소환 쿨타임 UI 구현)
- [버그] 발견된 오류 현상 (예: [버그] 기지 파괴 시 결과 팝업창이 뜨지 않는 문제)
- [에셋] 필요한 리소스 요청 (예: [에셋] 적군 타워 기지 도트 이미지 제작)
- [기획] 밸런스 및 레벨 디자인 (예: [기획] 1스테이지 적 유닛 스폰 주기 테이블 기획)

### 🏷️ 라벨(Label) 활용
- bug: 버그 수정 건
- enhancement: 새로운 기능 개발
- design: 그래픽/사운드 에셋 작업
- documentation: 기획서 및 매뉴얼 문서 작업

### 🔗 PR(Pull Request)과 이슈 연결
본인의 기능 개발 브랜치를 dev 브랜치로 PR 날릴 때, 본문 끝에 `Closes #이슈번호`를 적어두면 PR이 승인(Merge)될 때 해당 이슈가 자동으로 닫힙니다. (예: `Closes #12`)

## 6. Git 협업 규칙 & 브랜치 전략

- main (정식/출시 브랜치): 언제나 즉시 출시/플레이 가능한 안정 상태 유지
- dev (개발/통합 브랜치): 팀원들의 기능들이 매일 합쳐지고 테스트되는 기본 브랜치

### 작업 안전 루틴
1. 작업 시작 전 항상 Pull 먼저 받기 (최신 상태 동기화)
2. dev에서 본인의 기능 브랜치 생성 (예: feat/unit-movement, design/character-sprites)
3. 작업 완료 후 본인 브랜치로 커밋 및 푸시
4. GitHub에서 dev 브랜치를 향해 Pull Request (PR) 발송
